## Learned User Preferences

- When implementing work from an **attached plan**, **do not edit the plan file**; use the existing todo list (mark items in progress and complete them rather than recreating tasks).
- For major backend/output-engine refactors, keep the current operator UI visuals and interaction patterns stable unless the user explicitly asks for a UI change; explicit exceptions should be called out first.
- New Windows desktop work targets **WinUI 3** and the **Windows App SDK** (C# packaged), not WPF, Windows Forms, or new UWP.
- When asked to save git work, **run commit and push** in this repository instead of only describing steps.
- For C#/.NET align with `.agents/skills/dotnet-best-practices/SKILL.md`. For packaged build/launch follow `.cursor/rules/windows-build-verification.mdc` / `.cursor/skills/winapp-mcp-winui/SKILL.md`; WinApp MCP only when the task needs crash repro, functional testing, or in-app interaction (not routine UI/design unless asked). **Never** use Visual Studio F5, `dotnet run` on the WinUI project, `launch_app`, or raw `.exe` launch to verify.
- For contrast-sensitive WinUI surfaces (selected toolbar/toggle states, acrylic sidebars, transparent panels, slide cards), use transparency sparingly and preserve clear light/dark contrast on top of the doc rule to prefer ThemeResource/system brushes over hardcoded colors.
- For WinUI `DropDownButton` option pickers, prefer native `MenuFlyout` / `MenuFlyoutItem`; when options need rich visuals such as thumbnails, use a custom item style/template instead of replacing the menu with a generic `Flyout` + `ListView`.
- Before sweeping output-engine or layer refactors, remove stale gap-analysis and refactor-report docs from `docs/architecture/` and parallel app architecture folders; keep ProPresenter feature reference and target architecture explanations intact. During active development, prefer deleting and rebuilding to match reference/architecture docs over preserving transitional or legacy code paths; optimize for long-term ProPresenter parity, not in-repo backward compatibility.
- For theme, editor, settings, and Show surfaces, prefer clean app-native panels with progressive disclosure; avoid overusing description labels, redundant tooltips that repeat visible text, complex control surfaces, or exposing internal binding/system details unless the user explicitly asks for them. Keep tooltips on icon-only Show controls such as output layer clear buttons.
- For temporary UI redesign scaffolding or fake sample state, keep it clearly marked and remove or revert it before finalizing the work unless the user explicitly asks to keep it.
- When explaining native app work, use general contextual language grounded in workflow area and system (what changed, what is blocked, next step); avoid web/TypeScript analogies unless the concept is unfamiliar; do not lean on identifier lists without that framing.
- For top-level shell navigation, use native `SlideNavigationTransitionInfo` on `ContentFrame` for all SelectorBar routes including cached `ShowPage` reload. Compositor safety: `IShowRenderSession.ThumbnailRasterPhase` (`Blocked` during transition → `Returning` on cached `Loaded` → `OnFrameReady` after settle → `OffFrame` on `Unloaded`); never bind live compositor deck thumbnails mid slide-in — `IShowDeckThumbnailService` restores navigation pixel snapshots on revisit `Loaded` and defers compositor bind to `OnFrameReady`; preview attach only when `OperatorPreviewAttachAllowed`. Do not suppress Show transitions as a crash workaround.

## Learned Workspace Facts

- **Navigation & page state model**: the top-level SelectorBar navigation pattern, **cached `ShowPage`** in `ContentFrame` (`NavigationCacheMode.Required`), the `RoFailFast 0xC000027B` rationale, and transition rules are in `docs/architecture/platforms/winui-native-app.md` ("Top-level navigation and page state model"). **Editor, Reflow, Themes, Settings are fully transient** in `ContentFrame`. `ProgramRenderService` on `ProgramRenderAnchor` owns canonical output render. **Operator preview:** `OperatorPreviewSession` keeps one `ScreenMirrorBrush` on a shell overlay (`OperatorPreviewOverlayHost`); `ProgramOutputSurface` is a layout placeholder only — do not attach the session brush to the cached Show page. **Deck thumbnails:** `ISlideDeckThumbnailCache` + `IShowDeckThumbnailService` (`BeginRestoreNavigationDisplayOnLoaded`, `BeginCachePrefetch`, `PrepareForNavigationThumbnails`); raster only when `ThumbnailRasterPhase` is `OffFrame` or `OnFrameReady` (never `Blocked`/`Returning` compositor bind). Revisit `Loaded`: pixel snapshots restore immediately; cache prefetch may run during `Returning`; compositor surfaces bind after settle. On leave: evict compositor handles, keep navigation snapshots, deferred finalize releases row bindings. First load: `InitializeAsync` starts in `OnNavigatedTo`; thumbnail warm runs after deck build on the UI thread. Leaving Show: `NavigationService` → `ShowPage.TeardownForNavigation` once (preview overlay hide, thumbnail cancel, no double teardown from `OnNavigatedFrom`). All SelectorBar frame navigations use `SlideNavigationTransitionInfo` (`Hosting/ShellNavigation.cs`, `Hosting/ShellNavigationCoordinator.cs`). Transient-page CPU preview teardown: `NavigationTeardown.TeardownCompositionSurfaces`. Audience/stage title-bar toggles: `ShowViewModel` + `IOutputWindowService`. Solution: `apps/windows/ChurchPresenter/ChurchPresenter.slnx`.
- **Build & verification** (x64, repo root): **Toolchain** — `global.json` pins .NET SDK **10.0.301**; WinUI host TFM `net10.0-windows10.0.26100.0` with `TargetPlatformMinVersion` **10.0.17763.0**; libraries/tests `net10.0`; **Windows App SDK 2.2.0** (WinUI 3 via `Microsoft.WindowsAppSDK`). Repo style/analyzers: root **`.editorconfig`** only (no `Directory.Build.props`). Build: `dotnet build apps/windows/ChurchPresenter/ChurchPresenter.csproj -c Debug -p:Platform=x64` or `pwsh -File scripts/windows/Build-PackagedApp.ps1`. **Tests**: `dotnet test tests/ChurchPresenter.Core.Tests/...` and `tests/ChurchPresenter.App.Tests/...` (`Platform=x64`). **Packaged launch:** `Invoke-AgentE2EVerification.ps1` / `Run-PackagedApp.ps1`; launch scripts pick the **newest** `ChurchPresenter.exe` under `bin/x64/Debug/` (important after TFM bumps). **WinApp MCP** (`attach_to_pid`): only per task — crash repro, **functional** testing, or flows the agent must drive; **not** routine UI/design work unless the user asks. UI redesign: build suffices; user reviews visuals. **While iterating:** `Stop-ChurchPresenter.ps1` + relaunch before MCP or runtime checks; rebuild when needed (`-SkipTests -SkipBuild` for relaunch-only). Failure logs: `Run-PackagedApp.ps1 -Mode DebugOutput` → `.agent-logs/debug-output-*.log`. `dotnet format` does not load `.slnx`; run per relevant `*.csproj`.
- **Project organization**: Architecture docs in `docs/architecture/` (including [`formats/cpres-v1.md`](docs/architecture/formats/cpres-v1.md) and [`design-references.md`](docs/architecture/design-references.md)); ProPresenter behavior reference in `docs/reference/propresenter/` (read-only). Architecture-doc refresh via `.cursor/hooks/architecture-doc-refresh.ps1` and `.cursor/skills/architecture-doc-refresh/`. Parity reference is **ProPresenter docs + WinUI implementation**.
- **Content library lifecycle** (implementation specifics on top of `docs/architecture/content-management.md`): mutations go through `ILibraryRegistryService` / `IPlaylistRegistryService` and reload canonical catalog state. Playlist remove/reorder actions target the selected occurrence unless the operator chooses all matching instances.
- **Rendering / output runtime** (current code vs `docs/architecture/backend-application.md`): the unified cue pipeline lives under `ChurchPresenter.Application/Backend/Pipeline` (`Commands`, `Cues`, `Routing`, `Rendering`, `HostAdapter`, `Diagnostics`) — the actual path, not the doc's flatter `Backend/Cues` sketch. **Single canonical render + mirrors:** `ProgramRenderService` (DI singleton, `Adapters/Rendering/Pipeline/`) owns one `LayerStackHost` + `CompositionVisualSurface` per screen and implements BOTH `IAudienceHostAdapter` and `IStageHostAdapter` (registered as both in `RenderingPipelineHostRegistration`; passed to `CuePipelineRuntime` as audience+stage adapters). The pipeline applies each screen frame once; audience/stage windows mirror via `IProgramRenderService.GetScreenSurface`. **Operator preview** uses `OperatorPreviewSession` (shell overlay mirror, not a page-owned `MirrorSurfaceView` brush on cached Show reload). **Slide deck thumbnails** use `ISlideDeckThumbnailCache` + `ThumbnailEngine` with off-screen warm after Show departure — never raster from deck item property getters during Show navigation. There is no preview host adapter (`IPreviewHostAdapter` removed), no `OutputCompositorHost`/`WinUiAudienceOutputAdapter`/`WinUiStageOutputAdapter`/`WinUiPreviewAdapter`, and no `LayerStackHostView`. The canonical render is always on; `audienceEnabled`/`stageEnabled` gate only the output windows (`OutputWindowService`). Transparent slides on thumbnail, editor, reflow, and other non-output surfaces render over a theme-aware checkerboard (expected transparency preview, not a load failure); live audience/stage output must not (host owns fallback black).
- **WinUI composition & navigation gotchas**: `ItemsRepeater` does not populate `DataContext` on generated elements—use `Tag` with `x:Bind`. Prefer parameterless item-owned commands over typed `RelayCommand<T>` item templates (WinUI may set `Command` before `CommandParameter`). For packaged startup, create/activate `MainWindow` before settings/content bootstrap. Complex `ContentDialog` forms: XAML-backed with `ContentDialogSetup.ConfigureForPage(...)` before `ShowAsync`. Never pass WinRT method groups directly to `DispatcherQueue.TryEnqueue`—wrap in managed lambdas. Avoid synchronously disposing `CompositionObject`/`CompositionGraphicsDevice` while the compositor may still hold references.
- **Output layers / routing** (implementation specifics beyond `docs/architecture/backend-application.md`): UI/clear actions refer to **slide** vs **media** layers (not presentation vs media). The mask layer is routable from Looks but is **not** an output-preview clear target. Same-media replays reuse the existing `MediaPlayer`. Take-live media opens and begins playback before the enter transition (load-then-transition).
- **Show settings & transitions**: Global slide and media duration sliders use **100 ms** steps. Slide transition precedence: per-slide override → presentation-level (when set) → global toolbar; media uses per-item override else global fallback. Favorites/recents and toolbar transitions persist via `SettingsService` to `Configurations/Show.json`. Media seek forward/back uses `mediaSeekSeconds` (default 5, clamped 1–60).
- **Media drawer**: **Click** a media file card to send it to the **media output layer** only; **drag** onto a Show slide to attach or create **slide-linked media actions**. Thumbnails via **`MediaThumbnailLoader`**; startup/drawer warmup via **`IMediaThumbnailCache`** / **`IMediaStartupWarmupService`**.
- **Show slide interaction**: Normal slide-card click takes the slide live on the **slide output layer** without selecting; **Ctrl+click** and right-click select only; **Shift+click** range-selects; outside clicks clear selection only. Selection chrome and live chrome are independent; the green live ring reflects current unsuppressed `OutputLayerKind.Slide` program payload. Clearing the slide layer or deleting the final slide clears selection and keeps audience output blank. Presentations may have zero slides; new blank slides use a transparent background with no layers/text while preserving default text style.
- **Show sidebar**: Libraries and Playlists sections keep `NavigationViewItemHeader` headers visible when empty; hide search until searchable content exists. Empty sections use native sidebar-scale labels, not disabled nav items. Double-click toggles inline rename for the clicked row only.
